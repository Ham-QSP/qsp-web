# QSP Style Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create the `packages/qsp-style` sub-project holding QSP's visual identity, adopt it in the portal, and publish a Maven jar with its CSS at each release.

**Architecture:** `tokens.json` is the single source of values. A Node build script generates CSS and SCSS variables and compiles the base styles into one dependency-free CSS file. The portal reads the tokens directly; the release workflow packages the CSS in a jar under `META-INF/resources`.

**Tech Stack:** Yarn 1 workspaces, Node 22 (`node:test`), Sass, Vuetify 3, Maven, GitHub Actions and GitHub Packages.

**Spec:** `docs/superpowers/specs/2026-11-02-qsp-style-design.md`

## Global Constraints

- Dark theme only. Accent `#00A3FF`, text on accent `#0D1117`, background `#0D1117`, surface `#151B24`, border `#333D4D`, text `#E6E9EF`.
- Every text/background pair reaches WCAG AA (4.5:1).
- A colour is defined only in `tokens.json`; no hardcoded colour remains in the portal outside the logo.
- `qsp-style.css` has no dependency on Vuetify, Vue, a CDN or JavaScript.
- CSS variables and classes use the `qsp-` prefix.
- Maven coordinates `fr.f4fez:qsp-style`, published to GitHub Packages for `Ham-QSP/qsp-web`, at the version given to the `Release` workflow.
- `packages/qsp-style` is Apache-2.0; the rest of the repository stays AGPL-3.0-or-later.
- CSS served from `META-INF/resources/qsp-style/qsp-style.css`.
- The server repository is not modified.

## Review Focus

- Login popup is 400×500 px: a page using the classes must not scroll horizontally, even with a long error message.
- Browser autofill on a password field: fields must stay dark, so `color-scheme: dark` is required.
- Keyboard navigation: inputs, buttons and links show a visible `:focus-visible` state.
- A token is removed or renamed in `tokens.json`: the build fails with the role's name rather than emitting CSS with an empty variable.
- Pre-release version such as `1.2.3-rc.1`: the jar is produced with exactly that version.

**Interfaces:**
- Produces:
  - Package `@ham-qsp/qsp-style`, `private: true`, license `Apache-2.0`, `exports` for `./tokens.json`, scripts `build` and `test` (`node --test test/`), devDependency `sass` at root's version.
  - `tokens.json`: `{ color: { primary, onPrimary, background, surface, border, text, textSecondary, error, success, warning }, font: { sans, mono }, radius: { control, card } }`

  - Names: camelCase becomes kebab-case, so `color.onPrimary` gives `--qsp-color-on-primary` and `$qsp-color-on-primary`.
