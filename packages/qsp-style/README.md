# qsp-style

QSP's visual identity, shared by the portal (`qsp-web`) and the pages rendered by the authorization server.

`tokens.json` is the only place where values are defined. `yarn build` generates:

- `dist/qsp-style.css`: the `--qsp-*` CSS variables and the base styles, with no dependency.
- `dist/_tokens.scss`: the same values as `$qsp-*` Sass variables.

`yarn test` checks the tokens, their WCAG AA contrast and the generated CSS.

`example/login.html` shows a login page using only `qsp-style.css`. Build first, then open it in a browser.

## Use in a Spring server

### 1. Maven repository

The artefact is published to GitHub Packages at each `qsp-web` release. Reading it requires a GitHub token with the `read:packages` scope, declared in `~/.m2/settings.xml`:

```xml
<settings>
  <servers>
    <server>
      <id>github-qsp-web</id>
      <username>YOUR_GITHUB_USERNAME</username>
      <password>YOUR_TOKEN</password>
    </server>
  </servers>
</settings>
```

In the server's `pom.xml`:

```xml
<repositories>
  <repository>
    <id>github-qsp-web</id>
    <url>https://maven.pkg.github.com/Ham-QSP/qsp-web</url>
  </repository>
</repositories>
```

### 2. Dependency

```xml
<dependency>
  <groupId>fr.f4fez</groupId>
  <artifactId>qsp-style</artifactId>
  <version>1.2.3</version>
</dependency>
```

The version is the `qsp-web` release version.

### 3. Stylesheet

The jar contains `META-INF/resources/qsp-style/qsp-style.css`, which Spring Boot serves without configuration:

```html
<link rel="stylesheet" href="/qsp-style/qsp-style.css">
```

### 4. Spring Security

The login page is shown before authentication, so the stylesheet must be public:

```kotlin
http.authorizeHttpRequests {
    it.requestMatchers("/qsp-style/**").permitAll()
}
```

Without this rule, the login page loads without styles.

### 5. Login page

The server currently uses the login page generated by Spring Security, which these styles cannot reach. They apply once the server has its own login template, declared with `formLogin { it.loginPage("/login") }`.

## Classes

| Class | Element | Use |
|-------|---------|-----|
| `qsp-page` | `<body>` | Background, font, centres the card |
| `qsp-card` | `<main>` | Surface holding the content, up to 400 px wide |
| `qsp-title` | `<h1>` | Page title |
| `qsp-label` | `<label>` | Field label |
| `qsp-input` | `<input>` | Text and password fields |
| `qsp-button` | `<button>` | Main action, full width |
| `qsp-link` | `<a>` | Links |
| `qsp-error` | `<p role="alert">` | Error message |
| `qsp-success` | `<p role="status">` | Confirmation message |

Expected markup, as in `example/login.html`:

```html
<body class="qsp-page">
  <main class="qsp-card">
    <h1 class="qsp-title">Sign in to QSP</h1>
    <p class="qsp-error" role="alert">Invalid username or password.</p>
    <form method="post" action="/login">
      <input type="hidden" name="_csrf" value="...">
      <label class="qsp-label" for="username">Username</label>
      <input class="qsp-input" id="username" name="username" autocomplete="username" required>
      <label class="qsp-label" for="password">Password</label>
      <input class="qsp-input" id="password" name="password" type="password" autocomplete="current-password" required>
      <button class="qsp-button" type="submit">Sign in</button>
    </form>
  </main>
</body>
```

Other pages can use the variables directly, for example `color: var(--qsp-color-primary)`.
